커밋 그래프는 DAG

아래 단계 보기는 모두 같은 예시를 씁니다. 최초 커밋 뒤 main에서 결제 기능, feature에서 로그인 기능을 만들고 두 브랜치를 합친 상황입니다.

그래프
노드(커밋)와 간선(부모 연결)으로 이루어진 구조
DAG
간선에 방향이 있고, 따라가도 출발점으로 돌아오는 순환이 없는 그래프 (Directed Acyclic Graph)

화살표 = parents에 저장된 부모 hash. 화살표는 항상 과거(왼쪽)를 향함

  • 방향이 있음 : 커밋을 만들 때 앞 커밋은 이미 있고 뒤 커밋은 아직 없음 → 앞 커밋만 기억
  • 순환이 없음 : 이미 있는 커밋만 부모로 가리킬 수 있고, 만든 커밋은 바뀌지 않음 → 따라가면 결국 Initial commit에서 끝남
  • 트리가 아님 : merge 커밋은 부모가 2개 (parents=["78ca51e", "15809e9"])
  • 한 번 더 검증 : topological_sort()가 커밋을 다 출력하지 못하면 순환으로 보고 에러
커밋 (hash)parents
Initial commit 505181a[]
Add login feature 15809e9["505181a"]
Add payment feature 78ca51e["505181a"]
Merge branch 'feature' e7a1f20["78ca51e", "15809e9"]

저장은 commits = {hash: Commit} 해시맵. hash로 커밋을 평균 O(1)에 찾고, hash는 SHA-1 앞 7자리 (겹치면 다시 해싱해서 세션 안에서 중복 0개)

위상 정렬 : 부모가 항상 먼저

정의
방향 그래프에서 "A가 B보다 먼저"라는 간선 조건을 모두 지키도록 노드를 일렬로 나열하는 것
과제 요구
LOG는 최신순이 아니라 부모 커밋이 항상 자식보다 먼저 출력
왜
시각 순은 같은 초에 만든 커밋끼리 순서가 보장되지 않음 → 부모 관계(그래프 구조)만 보고 순서를 정해야 함

Kahn 알고리즘

  1. 커밋마다 "아직 출력 안 된 부모 수"를 셈
  2. 그 수가 0인 커밋을 큐(deque)에 넣음
  3. 하나 꺼내 출력하고, 자식들의 수를 1씩 줄임
  4. 0이 된 자식을 큐에 넣음 → 큐가 빌 때까지 반복
  • Merge는 부모 둘 다 출력된 뒤에야 큐에 들어감
  • 시간복잡도 O(V + E) : 커밋과 연결을 한 번씩만 봄
  • list.pop(0)은 O(N)이라 deque.popleft() O(1) 사용
PATH 15809e9 78ca51e · graph.shortest_path()

BFS 최단 경로

정의
시작점에서 가까운 노드부터 차례로 방문하는 탐색 (Breadth-First Search). 처음 닿은 거리 = 최단 거리
과제 요구
연결을 방향 없는 선으로 보고 선이 가장 적은 경로. 여러 개면 hash1->hash2->... 문자열이 사전순으로 가장 작은 것, 없으면 No path

두 단계로 찾음

  1. 도착점에서 BFS → 모든 커밋의 "도착점까지 남은 칸 수" 계산
  2. 출발점부터 이동 → 남은 칸 수가 1 줄어드는 이웃 중 hash가 가장 작은 것 선택
  • 도착점부터 재는 이유 : 한 칸 갈 때마다 "이 길도 최단인가"를 바로 판단 가능
  • 매번 가장 작은 hash면 되는 이유 : hash가 모두 7자라 경로 문자열 비교 = 앞 hash부터 차례로 비교
  • 예시의 최단 경로는 2개 (…→505181a→…, …→e7a1f20→…), 505181a < e7a1f20라서 앞쪽 선택
  • 시간복잡도 O(V + E)
ANCESTORS e7a1f20 · graph.find_ancestors()

조상 탐색 : 부모를 끝까지

정의
특정 커밋에서 부모 간선을 따라 도달할 수 있는 모든 커밋
과제 요구
도달 가능한 모든 조상을 빠짐없이 출력
  • 부모 방향으로만 BFS
  • visited 집합(set)에 이미 본 커밋을 기록 → 확인 O(1)
  • Initial commit은 두 길로 닿지만 두 번째는 건너뜀 → 결과에 한 번만
  • 가까운 조상부터 출력, 자기 자신은 제외
  • MERGE의 Already up to date. 판정(is_ancestor)에도 같은 함수를 씀

역색인 : 단어로 커밋을 바로 찾기

정의
"단어 → 그 단어가 들어 있는 커밋 목록" 형태로 미리 저장한 색인 (책 뒤의 찾아보기)
과제 요구
모든 커밋을 순회하지 않고 후보를 바로 가져올 것. 메시지를 공백으로 나누고 소문자로 바꾼 단어를 키로. keyword, author 2종

해 볼 것 : LOGIN (대소문자 무시), add login (모든 단어 포함), log (단어 단위라 못 찾음), --author=bob

역색인 : dict 조회1번 (검색어 단어 수만큼)
전체 훑기 : 확인할 커밋5개 (커밋이 늘수록 같이 늘어남)
예시 커밋 5개 (색칠 = 검색 결과)
keyword_index 키commit hash 목록

COMMIT 할 때마다 SearchIndex.add_commit()이 표를 갱신. 여러 단어는 첫 단어 목록과 나머지 단어 목록의 교집합. 시간복잡도 : 전체 훑기 O(N × 메시지 길이), 역색인 O(1) + 결과 수

정렬 직접 구현 : 병합 정렬

과제 요구
sorted(), list.sort() 사용 금지, 기준을 바꿔 정렬 (테스트가 소스에 두 API가 없는지 자동 검사)
안정 정렬
기준값이 같은 데이터는 원래 순서를 유지하는 정렬
선택 이유
최악에도 O(N log N), 안정 정렬이라 같은 작성자 안에서는 "부모 먼저" 순서가 그대로
지금 : LOG 기본 순서 (위상 정렬)

동그라미 숫자 = 정렬 전 순서. 정렬 뒤에도 Alice ①→③, Bob ②→④ 순서가 유지됨. 합칠 때 값이 같으면 왼쪽 원소를 먼저 넣기 때문 (key(left[i]) <= key(right[j]))
